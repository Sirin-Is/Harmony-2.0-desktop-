# Harmony

Desktop-застосунок для ведення обліку ФОП: картки клієнтів, доходи, податки, звітність, календар, кадри, виплата зарплати, журнал змін та резервний експорт.

Harmony працює локально навіть без інтернету. Дані зберігаються у SQLite на пристрої та, після входу, синхронізуються з Supabase між авторизованими пристроями одного робочого простору.

## Запуск для розробки

```powershell
npm.cmd install
npm.cmd run tauri dev
```

Застосунок відкривається як віконна програма Windows. Для перевірки лише інтерфейсу можна використати `npm.cmd run dev`, але SQLite, безпечна сесія та оновлення потребують Tauri.

## Збірка Windows

```powershell
npm.cmd run tauri build
```

Інсталятор з’явиться у `src-tauri\target\release\bundle\nsis`. Версія в `package.json` і `src-tauri\tauri.conf.json` має бути однаковою перед створенням релізу.

## Дані та синхронізація

- SQLite — основне локальне сховище. Редагування не залежить від доступності мережі.
- Supabase — репліка даних для синхронізації, а не єдине сховище для інтерфейсу.
- До Supabase передаються лише змінені записи. Віддалений курсор зберігає пару «час зміни + тип запису + ID», тому записи з однаковим часом не пропускаються.
- Якщо сервер недоступний понад 20 секунд, синхронізація зупиняється та автоматично повторюється пізніше. Локальні дані залишаються доступними.
- Профіль користувача кешується у захищеному сховищі сесії, тому останній авторизований користувач може відкрити застосунок офлайн.

Не видаляйте файл локальної бази даних, якщо не маєте актуального експорту. Перед перевстановленням або перенесенням на інший пристрій створіть резервну копію через інтерфейс Harmony.

Адміністратор може створити або відновити повну резервну копію у «Налаштування → Загальні → Резервна копія». Кожна нова копія шифрується окремим паролем; Harmony не зберігає пароль, тому його втрата унеможливлює відновлення файлу. Перед відновленням файл проходить перевірку структури. Після цього Harmony спершу порівнює копію з усіма даними робочого простору; розбіжності не перезаписуються, а з’являються в «Налаштування → Конфлікти» для окремого рішення.

У «Налаштування → Діагностика» адміністратор може виконати read-only перевірку SQLite (`quick_check`) і переглянути останні операції синхронізації. Там само відображаються помилкові посилання на відсутніх ФОП. Якщо перевірка повідомляє про проблему, не продовжуйте масове редагування: створіть актуальну резервну копію, збережіть повідомлення діагностики й відновіть дані з перевіреної копії за потреби.

## Ролі

- **Адміністратор** — повний доступ, зокрема до «Налаштування → Користувачі», відновлення резервних копій і відкату змін за останні 7 днів.
- **Бухгалтер** — редагує облік, але не керує користувачами.
- **Спостерігач** — переглядає дані без редагування та експорту.

Інтерфейсні обмеження — лише зручність. Реальний захист даних забезпечують Supabase Auth, RLS-політики та перевірка ролі на сервері. Не додавайте `service_role` або інші секретні ключі у фронтенд, конфігурацію Tauri чи GitHub Actions logs.

## Налаштування Supabase

Після клонування репозиторію застосуйте міграції до вже прив’язаного проєкту:

```powershell
npx supabase migration list
npx supabase db push
npx supabase functions deploy manage-harmony-users
```

Усі таблиці `public` повинні мати увімкнений RLS. Після зміни міграцій перевіряйте Database Advisors у Supabase Dashboard. Облікові записи Auth та їхні логіни керуються з Harmony: «Налаштування → Користувачі».

## Автоматичні оновлення

Збірки для Windows публікуються GitHub Actions workflow `.github/workflows/release.yml`. Для підписання оновлень потрібні секрети репозиторію з приватним ключем Tauri; приватний ключ ніколи не додається до Git.

Перед публікацією нового релізу:

1. Підвищте версію в `package.json` та `src-tauri/tauri.conf.json`.
2. Перевірте `npm.cmd run build` і `npm.cmd run tauri build` на Windows.
3. Перевірте створений інсталятор і сценарій оновлення поверх попередньої версії.

## Перевірки перед змінами

```powershell
npx.cmd tsc --noEmit
npm.cmd test
npm.cmd run build
git diff --check
```

Пакети зафіксовані точними версіями у `package.json` та `package-lock.json`, щоб повторні установки не отримували випадкові несумісні оновлення Tauri.

## Ручний чек-лист перед релізом

1. У встановленій Windows-версії увійти як адміністратор, створити ФОП, додати дохід і перевірити статус «Локально та синхронізовано».
2. Створити зашифровану резервну копію, переконатися, що неправильний пароль її не відкриває, і перевірити відновлення на тестових даних.
3. У «Налаштування → Діагностика» виконати перевірку локальної бази: очікуваний статус — «Справна».
4. Перевірити ролі: бухгалтер не бачить «Користувачі», а спостерігач не може змінювати дані чи експортувати їх.
5. Перевірити інсталятор на чистому профілі Windows і оновлення поверх попередньої версії.
